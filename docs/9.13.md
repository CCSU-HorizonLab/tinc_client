# 2026-09-13 开发与排查问题汇总记录 (Docs / 9.13.md)

本文档记录了在 **Tinc Client (Tauri Desktop GUI + Rust Agent)** 开发调试过程中于 2026年9月13日 遇到的所有核心问题、根因分析及对应解决方案。

---

## 1. TAP 虚拟网卡名称不匹配

- **问题现象**：
  Tinc 启动失败，后台日志输出 `No Windows tap device found!`。
- **根因分析**：
  Windows 系统上通过驱动创建的 TAP 网卡名称默认为 `tinc0`，但项目的配置文件 `settings.json` 和 `tinc.conf` 中指定的是 `Interface = tinc`。Tinc 1.0.x 会根据 `Interface` 字段指定的精准名称去查找网卡。
- **解决办法**：
  在管理员权限的 PowerShell 中执行网卡重命名：
  ```powershell
  Rename-NetAdapter -Name "tinc0" -NewName "tinc"
  ```

---

## 2. 虚拟网卡 IP 设置提示需要管理员提权 (Elevation Required)

- **问题现象**：
  UI 提示 `虚拟网卡配置失败 (exit=1)`，详细错误日志为：
  `stdout: The requested operation requires elevation (Run as administrator).; stderr:`
- **根因分析**：
  Agent 在启动 `tincd.exe` 后，需要调用 Windows 系统工具 `netsh.exe` 给 TAP 虚拟网卡配置 IP 地址（如 `10.0.11.211`）。以普通用户身份运行 Agent 会因为缺乏管理员权限而被 `netsh` 拒绝。
- **解决办法**：
  1. 后台 Agent (`vpn-agent.exe`) 必须以管理员权限运行。
  2. 创建了自动提权一键启动脚本 `scripts/dev/launch.ps1` 及桌面快捷方式 **「Tinc Connect」**（配置了 `RunAs` 属性），实现了双击图标自动弹出 UAC 提权并后台静默拉起 Agent 和 UI 界面。

---

## 3. 桌面 UI 日志输出无法框选及一键复制

- **问题现象**：
  用户在 GUI 界面的“活动日志”面板中无法使用鼠标拖动选中文本，且点击“复制日志”按钮没有任何响应。
- **根因分析**：
  1. **样式限制**：Tauri / WebKit 环境下，默认继承了文本不可选中特性，且 CSS 中缺少 `user-select: text`。
  2. **剪贴板 API 兼容性**：`navigator.clipboard.writeText` 在非 Secure Context (HTTP / 本地 Tauri 开发模式) 或窗口未聚焦时，会静默抛出 `DOMException` 导致逻辑中断。
- **解决办法**：
  1. **CSS 样式强行覆盖** (`apps/desktop/src/styles/main.css`)：
     在 `.log-body` 和 `.log-line` 样式中加入：
     `user-select: text !important; -webkit-user-select: text !important; cursor: text;`
  2. **双重兼容剪贴板函数** (`apps/desktop/src/App.vue`)：
     引入基于 DOM 动态 `<textarea>` + `document.execCommand('copy')` 的兼容复制方案作为优先选择，并加入右键选中文本即复制 (`@contextmenu`) 和状态反馈（`✓ 已复制` / `❌ 复制失败`）。

## 4. Clash Verge / Mihomo TUN 模式拦截 Tinc 握手流量

- **问题现象**：
  Tinc 进程显示启动成功，但连接状态持续处于 `CloseWait` / `TimeWait`，无法与远程服务器 `8.148.13.80:600` 完成组网密钥握手。
- **根因分析**：
  本机运行了 `Clash Verge` (`verge-mihomo`) 并开启了全局 TUN 模式。Clash TUN 虚拟网卡 (`198.18.0.1`) 优先拦截并接管了所有 TCP/UDP 流量（包括发往 `8.148.13.80:600` 的原始握手包），破坏了 Tinc 的点对点 (P2P) 加密握手。
- **解决办法**：
  1. 临时排查：关闭 Clash Verge 的 TUN 模式或暂停代理。
  2. 长期解决：在 Clash Verge 路由/绕过规则 (Bypass / Direct) 中，将服务器 IP `8.148.13.80` 及内网网段 `10.0.11.0/24` 显式设置为 `DIRECT` (直连)。

## 5. `/32` 地址缺少独立对端路由导致 `TTL expired in transit` 报错

- **问题现象**：
  在终端中执行 `ping 10.0.11.1` 时，提示 `Reply from 10.0.100.2: TTL expired in transit`（传输中 TTL 过期）。`tracert` 路由跟踪显示数据包跑到了本地物理路由器和运营商外网节点。
- **根因分析**：
  - `node_ip/32` 是后端已经确认的正确契约，不能改为 `/24`。问题是设置 `/32` 地址后没有同时创建到对端的独立路由，Windows 路由表仅将精准地址 `10.0.11.211` 绑定在 `tinc` 网卡上。
  - 当 Ping `10.0.11.1` 时，Windows 在 `tinc` 网卡上找不到匹配路由，便将数据包投递给了默认物理外网网关。运营商上游节点 `10.0.100.2` 收到私有 IP 后在内部路由节点间循环转发，直到 TTL 减为 0 报错。
- **解决办法（已纳入 Agent）**：
  - 从严格校验的 `hosts/server_master` 读取唯一 `Subnet`，当前为 `10.0.11.1/32`。
  - 启动时创建 `10.0.11.1/32 -> tinc` 的 active 路由，停止、异常退出及恢复清理时只删除这条精确路由。
  - 不猜测整个网络为 `/24`；若后续需要访问其他节点，后端必须提供明确的路由契约。
